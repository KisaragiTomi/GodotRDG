# Legacy 屏幕空间 RC 回归副本

2026-09-24。来源：`D:/MyProject/GI-POE/project/scripts/rc_effect.gd` 和四个 `rc_*.glsl`。原工程未修改。副本放在 `legacy_rc/`，类名为 `LegacyRadianceCascadesEffect`，资源路径全部指向本目录。

这是审计问题的回归参考，**不是本工程的 topdown GI 实现**。默认主场景没有挂载它，不应以这个副本评估世界空间 topdown GI 的画质或性能。

## 已修改

- 远到近合并时，在每两个相互依赖的 dispatch 之间调用 `compute_list_add_barrier()`。这里使用 Godot 4.6.1 `rendering_device.cpp` 中实际结束当前 list、启动下一 list 并恢复绑定的接口，不使用已废弃的全局 `barrier()`。四次 merge dispatch 之间有三处同步。
- 新增 `rc_probe.glslinc`，build、merge 和 apply 共用同一探针位置公式。位置抖动只依赖探针坐标和级联编号，范围为每轴 ±0.15 probe spacing；不再依赖方向编号。深度读取采用该抖动位置对应的同一 texel。
- merge 和 apply 根据实际抖动位置计算 tent 权重并归一化，查询周围 3×3 探针，以覆盖抖动后的支持范围。它是位置一致的平滑近似，不是对不规则网格的精确双线性插值。屏幕边缘的探针位置统一钳制到像素中心范围。
- 角度采用固定 bin 中心，去除旧 angular jitter，使 build、merge 的方向分组与 apply 的方向重建一致。
- apply 丢弃无几何背景探针和 `depth_w < 0.05` 的探针，不再把权重强制抬升到 0.05。无有效权重时明确返回零间接光；普通输出保留场景色，`INDIRECT_ONLY` 输出黑色。背景像素在 `INDIRECT_ONLY` 下也输出黑色。
- apply 的深度差法线采样钳制到屏幕边界，避免边缘 texelFetch 越界。merge 无有效远级联样本时保留透射率 1、增加辐射 0。
- merge 的 push constants 增至 64 字节，传入屏幕尺寸及两级 cascade index，使共享位置公式可在两级上重建同一采样位置。

## 明确保留的局限

1. **屏幕空间**：只访问当前相机可见颜色和深度。没有屏幕外、遮挡后或背面几何的信息，没有世界空间稳定性保证。
2. **不是三维射线**：方向仍为二维屏幕方向，射线沿 XY 前进时使用固定起点深度和 thickness 启发式。高低层、桥下、墙到地面的传播没有被解决。
3. **材质响应不正确**：源数据仍为已经着色的 scene color，可能混入镜面；接收端仍直接加颜色，没有 albedo、金属度或真实表面法线输入。这些修复不构成物理正确 GI。
4. **仍限透视反向 Z**：深度线性化仍使用用户填写的 near/far 公式，没有真实投影矩阵。正交相机不受支持；不要把它接入本工程的正交 topdown 路径并当作正确对照。
5. **合并仍不保证可见性**：merge 插值没有深度或几何拒绝。apply 对近级联做拒绝，无法撤销已经在远级联合并中混入的错误颜色。同深度薄墙也不能靠接收端深度阈值隔离。
6. **拒绝仍是启发式**：沿用原有 depth thickness 与相对深度尺度，0.05 是明确的接受阈值。全部拒绝可能产生暗洞；零 GI 是保守回退，未增加搜索补洞、历史补偿或时间降噪。
7. **参考实现非性能目标**：3×3 重建比旧 2×2 更贵；原有五级 atlas、射线步进和全分辨率 apply 保留。性能优化应针对 topdown 世界网格路径，而非为自由 3D 视角继续扩展这个副本。
8. **原有资源生命周期与视图约束保留**：只处理 view 0，依赖 RenderingDevice 的 compositor 回调和已解析颜色/深度；不是多视图、VR、Compatibility 渲染器方案。

## 验证边界

源代码层面已核对 barrier 所在的远到近依赖循环、64 字节 merge 参数布局以及三处共享探针位置调用。尚未单独运行这个 legacy compositor，因此不能宣称漏光已消失、画质改善或某 GPU 后端问题已实测解决。

可复现对照应使用透视场景相机，将 near/far 与 effect 参数保持一致，分别观察正常输出、`INDIRECT_ONLY` 和 `CASCADE_ATLAS`。至少检查薄墙、深度断层、屏幕边缘及全部邻居被拒绝的接收面，并记录渲染后端。默认 topdown 场景的运行结果不代表此副本完成了回归测试。
